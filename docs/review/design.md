# 화면 기준

디자이너가 없는 프로젝트라 이 문서가 디자인 기준이다. `ui-consistency-review` 스킬은 이 문서를 일반 기준보다 우선한다.
지금 화면(처음, 글 목록, 글 화면)에서 뽑아낸 기준에 [v0.3 PRD](https://github.com/es-kimo/content-editor/wiki/v0.3-PRD) §4·§5의 화면 정책을 더했다. 사람이 고치는 문서다. 에이전트 PR은 수정할 수 없고, 새 패턴이 필요하면 PR 본문 `## 리뷰 포인트`에 기준 제안으로 적는다.

## 원칙

1. **도구다.** 글을 고치고 커밋하는 작업 화면이다. 장식, 그림자, 그라데이션, 애니메이션을 넣지 않는다.
2. **흑백에 의미 색만.** 색은 상태를 알릴 때만 쓴다. 강조는 굵기와 크기로 한다.
3. **글이 먼저다.** 글을 열면 파일 경로가 아니라 제목과 본문이 먼저 보인다. 설정과 기술 정보는 접어 둔다.
4. **원문을 숨기지 않는다.** 일반 편집으로 고칠 수 없는 글은 이유를 보여 주고 원문 편집으로 안내한다. 조용히 빼지 않는다.
5. **입력을 잃지 않는다.** 저장이 실패해도 입력은 남고, 오류는 그 필드 옆에 보인다. 오류와 미저장 표시는 접힌 영역에 가려지지 않는다.

## 토큰

Tailwind 기본 팔레트를 쓰고, 역할마다 값 하나만 쓴다.

| 역할                                    | 값                                                                                          |
| --------------------------------------- | ------------------------------------------------------------------------------------------- |
| 본문                                    | 기본 전경색 (`--foreground`)                                                                |
| 보조 설명, 메타 정보, 로딩              | `text-zinc-500`                                                                             |
| 오류, 권한 없음                         | `text-red-600`                                                                              |
| 경고, 미저장, 폼으로 못 고침, 읽지 못함 | `text-amber-600`                                                                            |
| 성공 (저장함)                           | `text-green-700`                                                                            |
| 주 버튼                                 | 검정 바탕 흰 글자, 다크 모드는 반전. `rounded px-4 py-2`                                    |
| 페이지 셸                               | `mx-auto flex w-full max-w-3xl flex-col gap-6 px-6 py-16`                                   |
| 글자 크기                               | 페이지 제목 `text-2xl font-semibold`, 절 제목 `font-medium`, 본문 `text-sm`, 보조 `text-xs` |
| 간격                                    | 페이지 절 사이 `gap-6`, 절 안 `gap-2`, 라벨과 입력 `gap-1`                                  |

## 글 화면 배치

위에서 아래로 이 순서다. 새 영역을 넣을 때도 제목·본문보다 위에 두지 않는다.

1. **화면 제목**: 저장된 글 제목. 제목이 없으면 ‘제목 없는 글’. 파일 경로를 제목 자리에 쓰지 않는다. 글 목록도 같은 규칙으로 제목을 보인다.
2. **제목 입력**: 편집할 수 있는 글에서만 보인다. 글 설정과 같은 저장 대상이라 ‘글 설정 저장’으로 저장한다. 본문과 함께 저장하거나 입력 즉시 저장하지 않는다.
3. **본문**: 일반 편집 또는 원문 편집. 기본 모드는 글 설정이 정한 대로 둔다. 원문 전용 글이면 본문 위에 제한 이유를 보인다.
4. **글 설정** (기본 접힘): 제목을 뺀 나머지 설정 필드.
5. **기술 상세** (기본 접힘): 파일 경로, blob SHA, 커밋 식별자, API 호출 수·시간, 기술 오류 원문.

### 접힌 영역

- 접힌 영역의 요약 줄에는 영역 이름과 상태가 보인다. 안에 오류가 있으면 오류 색으로, 저장하지 않은 변경이 있으면 미저장 표시를 요약 줄에 둔다. 펼쳐야만 알 수 있는 상태가 없어야 한다.
- 저장하면서 숨겨진 필드에 입력 오류가 나면 그 영역을 펼치고 오류 필드 옆에 메시지를 둔다.
- 사용자가 알아야 할 결과(저장 성공·실패, 충돌, 일반 편집 제한과 그 이유)는 기본 화면에 둔다. 기술 상세에는 그 결과의 기술 원문만 덧붙인다. 기술 상세 내용이 기본 안내를 대신하지 않는다.

### 글 설정 필드

- 설정에 있는 필드·필수 조건·상태 값을 모두 보인다. 알 수 없는 필드나 값도 빼지 않는다.
- 라벨은 설정의 사용자 라벨을 우선한다. 없으면 알려진 필드는 제목·요약·검색어·작성일·상태처럼 쓴다.
- 상태 값은 `ready`를 ‘게시 대상’, `draft`를 ‘초안’으로 보인다. 저장하는 값은 바꾸지 않는다. ‘게시 대상’은 사이트에 반영됐다는 뜻이 아니다.

## 컴포넌트와 상태

- 링크는 밑줄 텍스트다. 버튼처럼 꾸미지 않는다. 예외: 글 분류 탭(`aria-current`로 반전).
- 로딩: `Suspense` fallback `<p className="text-zinc-500">불러오는 중…</p>`.
- 빈 목록: 무엇이 없는지와 조건을 한 문장으로 (`` `<path>`에 맞는 글이 없어요. ``).
- 오류: 무엇이 안 됐는지 + 무엇을 하면 되는지. 예시는 [안내 예시](#안내-예시).
- 로그인이 필요하면 설명 없이 로그인 버튼(`LoginLink`)만 보인다.
- 저장 버튼은 범위를 이름에 담는다: ‘글 설정 저장’, ‘본문 저장’, ‘원문 저장’.

## 메뉴와 폼

넣기 메뉴, 넣기·수정 폼, 접힌 영역에 적용한다.

- **키보드**: 마우스 없이 열고, 항목 사이를 옮기고, 고르고, 닫을 수 있다. `Esc`는 메뉴와 폼을 닫는다. 접힌 영역은 `<details>`/`<summary>` 또는 `aria-expanded`가 있는 버튼으로 여닫는다.
- **이름**: 메뉴, 메뉴 항목, 폼, 입력, 아이콘만 있는 버튼은 화면 낭독기가 읽을 이름이 있다. 넣기 메뉴 항목은 ‘이미지’, ‘각주’, ‘각주 출처’, ‘목차’처럼 용도로 부른다. 컴포넌트 이름(`Footnote`, `TOC`)을 이름으로 쓰지 않는다.
- **초점**: 메뉴나 폼을 열면 초점이 그 안 첫 조작 요소로 간다. 적용·취소·`Esc`로 닫으면 연 버튼이나 연 항목으로 초점을 돌린다.
- **적용과 취소**: 폼은 ‘적용’ 때만 본문을 바꾼다. ‘취소’는 아무것도 바꾸지 않는다. 적용하지 않은 폼이 열려 있으면 저장·모드 전환 전에 적용하거나 취소하라고 안내한다.

## 좁은 화면

- 화면은 한 열이다. 보조 영역(글 설정, 기술 상세, 미리보기, 삽입 항목 목록)을 본문 옆에 둔 화면이라도 좁은 화면에서는 본문 다음으로 내린다.
- 원문 코드 영역 외에는 가로 스크롤 없이 주요 작업(글 열기, 설정 수정, 넣기, 재편집, 저장)을 할 수 있다. 긴 파일 경로·SHA·URL은 줄을 바꾼다(`break-all`).
- 폭 360px 화면에서 가로 넘침이 없는지 확인한다.

## 문구

화면에 보이는 안내, 버튼, 라벨, 오류에 적용한다. 코드 주석, 테스트 이름, 이 문서 같은 개발 문서와 글 본문 자체의 말투는 대상이 아니다.

- 해요체로 쓴다: “저장했어요”, “글을 찾을 수 없어요.” 부탁은 “~해 주세요”로 쓴다. 해라체·합쇼체를 섞지 않는다.
- 안내는 사용자가 할 행동으로 끝낸다. 개발 용어(config, metadata, blob, WYSIWYG, import)를 기본 안내에 쓰지 않는다.
- 버튼은 짧은 행동 이름이다: ‘저장’, ‘넣기’, ‘적용’, ‘취소’. 범위를 나눠야 할 때만 대상을 붙인다(‘본문 저장’).
- 같은 대상은 같은 이름으로 부른다.

| 쓰는 말   | 쓰지 않는 말         |
| --------- | -------------------- |
| 글        | 포스트               |
| 글 설정   | metadata, 메타데이터 |
| 일반 편집 | WYSIWYG              |
| 원문 편집 | source, 원문 모드    |
| 글 분류   | 컬렉션, collection   |
| 레포      | 저장소               |

### 안내 예시

저장 성공과 사이트 반영은 다른 일이다. 저장 성공만으로 게시나 반영이 끝났다고 말하지 않는다.

| 상황                  | 안내                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------- |
| 저장 성공             | 저장했어요. 사이트에 반영되기까지 시간이 걸릴 수 있어요.                                    |
| 변경 없음             | 변경된 내용이 없어요.                                                                       |
| 입력 오류             | 필드 옆에: 제목을 입력해 주세요.                                                            |
| 충돌                  | 글을 연 뒤 다른 곳에서 글이 바뀌었어요. 입력한 내용을 따로 보관한 뒤 글을 다시 열어 주세요. |
| 원문 전용 글          | 이 글은 일반 편집을 지원하지 않아요. 원문 편집을 이용해 주세요. + 구체적인 제한 이유        |
| 미저장 변경           | 저장하지 않은 변경이 있어요. 바뀐 곳: 본문, 글 설정                                         |
| 적용하지 않은 폼      | 열려 있는 폼을 먼저 적용하거나 취소해 주세요.                                               |
| 목차를 채울 제목 없음 | 글에 제목을 추가하면 목차가 채워져요.                                                       |

오류 응답 원문이나 커밋 식별자는 기본 안내를 대신하지 않는다. 필요하면 기술 상세에 둔다.

## 결정 필요

사람이 정해서 이 문서에 반영한다. 정하기 전까지 리뷰는 이 항목을 blocking으로 올리지 않는다.

- 디자인 시스템(공용 컴포넌트 디렉터리, 토큰을 CSS 변수로)을 언제 도입할지. v0.3은 전체 디자인 시스템 재구축을 범위 밖으로 둔다.
